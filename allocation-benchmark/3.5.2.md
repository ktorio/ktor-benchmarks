## Allocation Benchmark Results: 3.5.1 → 3.5.2

> ⚠️ This report was generated with AI assistance and may contain incorrect attributions or false claims. Please verify before publishing.

### Key Takeaways

**Improvements**

- **Netty allocates 508 bytes less for file responses and 680 bytes less (7.8%) for simple responses.**
  [#5746](https://github.com/ktorio/ktor/pull/5746) caches connection-stable coroutine context elements and replaces the per-call response-writer join with structured concurrency. Call-site data confirms reductions in `NettyHttp1Handler`, `NettyApplicationCall`, and `SuspendFunctionGun`.

- **Encoding a simple text response allocates a 32-byte array instead of a 216-byte array on every server engine.**
  [KTOR-9704 / #5743](https://github.com/ktorio/ktor/pull/5743) restores the JVM-optimized UTF-8 encoding path used by `TextContent`, saving 184 bytes per response before engine-specific offsets.

**Regressions**

- **Buffered UTF-8 line handling adds 112 bytes while parsing CIO server requests and about 64 bytes in affected CIO client paths.**
  [KTOR-9679 / #5766](https://github.com/ktorio/ktor/pull/5766) buffers incomplete multi-byte characters correctly, and [KTOR-9743 / #5778](https://github.com/ktorio/ktor/pull/5778) preserves partial output and byte-limit behavior on failures. The increase comes from the captured output-buffer reference in `internalReadLineTo`.

- **Tomcat's async context allocates 88 bytes more per request.**
  [#5772](https://github.com/ktorio/ktor/pull/5772) updates Tomcat Jakarta from 10.1.55 to 10.1.57. No Ktor servlet source changed, and both Tomcat scenarios show the same `AsyncContextImpl` increase.

**Measurement artifacts and minor changes**

- **Small client movements are dominated by coroutine suspension timing rather than changed allocation sites.**
  The streaming totals move by +345 bytes for CIO, −63 bytes for Apache, −402 bytes for Java, and +581 bytes for OkHttp. No `ByteChannel` or `ByteWriteChannelOperations` source changed in this release. OkHttp's 694-byte decrease in arrays under `OkHttpEngine.toChannel` matches the documented scheduler-dependent segment-pool variance and is well within its 278,528-byte bound.

- **The apparent 82-byte `Endpoint.kt` improvement is one-time JVM class-loading noise.**
  The four timeout-coroutine allocations total 136 bytes in both versions; only class-loader, JAR, URL, and security-support allocations attributed to the first `delay` invocation disappeared.

- **The apparent 59-byte `ApacheHttpRequest.kt` improvement is lazy Apache header-array variance.**
  It appears only in the gzip scenario, while all other allocations at the site and all other Apache scenarios are unchanged.

- **Body-less Java GET requests avoid a 40-byte publisher allocation.**
  [KTOR-9588 / #5620](https://github.com/ktorio/ktor/pull/5620) now uses the JDK client's direct `GET()` path when there is no body. The surrounding `TreeMap` additions and removals are source-line relocation and cancel out.
