## Allocation Benchmark Results: 3.4.2 → 3.4.3

> ⚠️ This report was generated with AI assistance and may contain incorrect attributions or false claims. Please verify before publishing.

### Key Takeaways

**Improvements**

- **Coroutine wrapper overhead eliminated on the pipeline fast path; saves ~160–393 bytes per server request across all engines.**
  [KTOR-9431 / #5503](https://github.com/ktorio/ktor/pull/5503) — `SuspendFunctionGun` now stores raw continuations instead of `DispatchedContinuation` wrappers, removing extra coroutine objects per pipeline step.

- **Apache 5 client: fewer `ByteChannel.awaitContent` suspensions when reading responses, thanks to `resultCallback` now being properly invoked on stream completion.**
  [KTOR-9485 / #5526](https://github.com/ktorio/ktor/pull/5526) — saves ~167 bytes for `helloWorld`, ~1,193 bytes for `fileResponse`, ~7,370 bytes for `gzipResponse`, and ~4,852 bytes for `streamingResponse`.

**Regressions**

- **Netty: ~100 bytes added per request by inlining call execution into `NettyHttp1Handler`.**
  [KTOR-9343 / #5421](https://github.com/ktorio/ktor/pull/5421) — `NettyApplicationCallHandler` removed and its logic inlined into `NettyHttp1Handler` to fix incorrect `call.coroutineContext` scope; `NettyHttp1Handler` grew by +928 bytes, partially offset by eliminating `NettyApplicationCallHandler` (−520 bytes) and simplifying `NettyApplicationCall` (−216 bytes). Net Netty result remains positive due to the SFG improvement above.
